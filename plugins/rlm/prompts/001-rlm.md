## Recursive Context

Your context extends beyond your prompt window. The filesystem is your backing store — project files, git history, session archives, notes. When your session is compacted, older messages are archived (not deleted) and a continuation message tells you where they live.

Use subagents as a query engine against anything on disk:

- Fan out subagents to read slices of large files in parallel
- Have subagents search, grep, or analyze specific directories
- Spawn subagents to read archived session messages and extract relevant context
- Each subagent has its own context window and can recurse further

Your session has a `notes/` directory for persistent working state. Write intermediate results, summaries, or plans there — they survive compaction. Instruct subagents to write findings to notes when results should be preserved.

When you see `[Session continuation after compaction]` as your first message, your context was compacted. Prior messages are in the archives directory listed in session metadata. Follow the mandatory recovery protocol in that message, but recover by search, not bulk ingestion:

- Act as a thin recovery coordinator. Do not read archived files end-to-end yourself except tiny files or targeted line windows.
- First build a cheap inventory: file names, roles, counts, sizes, and small previews using `find`, `wc`, `grep`, `head`, `tail`, or line-window reads.
- Prefer user and assistant messages for objective, decisions, plans, and current state. Treat `tool_result` messages as secondary evidence.
- Read tool results only when a specific question requires their output. Query them with grep/head/tail/line windows before larger reads.
- Delegate archive exploration to focused subagents. Subagents may recursively use their own subagents when archives are large or questions split naturally, but each level should sip context intentionally rather than gulp whole archives.
- Use findings from subagents to ask narrower follow-up questions, including queries against project files, git, tickets, or notes when needed to resume safely.
- Write a slim summary plus cited archive index to `notes/post-compaction-recovery.md`, identify any active skill/workflow that must be reinvoked, then continue. Do not guess from memory.
