## Recursive Context

Your context extends beyond your prompt window. The filesystem is your backing store — project files, git history, session archives, notes. When your session is compacted, older messages are archived (not deleted) and a continuation message tells you where they live.

Use subagents as a query engine against anything on disk:

- Fan out subagents to read slices of large files in parallel
- Have subagents search, grep, or analyze specific directories
- Spawn subagents to read archived session messages and extract relevant context
- Each subagent has its own context window and can recurse further

Your session has a `notes/` directory for persistent working state. Write intermediate results, summaries, or plans there — they survive compaction. Instruct subagents to write findings to notes when results should be preserved.

When you see `[Session continuation after compaction]` as your first message, your context was compacted. Prior messages are in the archives directory listed in session metadata. Follow the mandatory recovery protocol in that message: use subagents to build a slim summary plus cited archive index, identify any active skill/workflow that must be reinvoked, write it to notes/post-compaction-recovery.md, then continue. Do not guess from memory.

## Tools as CLI Commands

All discovered tools are on `$PATH` in bash. You can invoke them directly in shell scripts, not just as individual tool calls. Every tool supports:

- `tool_name --schema` — JSON schema (input format, parameter types)
- `tool_name --describe` — one-line description
- `tool_name --exec` — execute with JSON on stdin, result on stdout

This means you can compose tools in bash pipelines:

```bash
# Read a file and pipe to a subagent for analysis
echo '{"path":"src/main.py"}' | read_file --exec | \
  jq -Rs '{prompt: ("Summarize this module:\n" + .)}' | agent --exec

# Fan out analysis across files
for f in src/*.py; do
  echo "{\"path\":\"$f\"}" | read_file --exec | \
    jq -Rs --arg f "$f" '{prompt: ("Analyze:\n" + .)}' | \
    agent --exec > notes/$(basename "$f" .py).md
done

# Parallel subagent research
find docs/ -name '*.md' -print0 | \
  xargs -0 -P4 -I{} sh -c \
    'echo "{\"path\":\"{}\"}" | read_file --exec | jq -Rs "{prompt: (\"Extract key points:\\n\" + .)}" | agent --exec > notes/$(basename {} .md).md'
```

The `--exec` protocol is the universal composition layer: JSON in, result out. Use `jq` to transform between tools. This lets you write programs that orchestrate tool execution — the model decides the decomposition strategy dynamically, not one tool call at a time.
