<simplicity_reminder>
Before you finish ANY task, ask yourself:

1. Is this the simplest implementation? No over-engineering, no unnecessary abstractions?
2. Is it free of complecting? Each component does ONE thing, concerns are separated?
3. Can it be even simpler? Is there a more direct approach?
4. Did I consolidate duplication I found? Or leave technical debt behind?
5. Do tests pass? No hidden breaks.
6. Is the intent clear? Can a reviewer understand the approach at a glance?

For features: Did I add this behavior in the simplest possible way?
For refactors: Did I actually reduce complexity in the resulting code?
For bugs: Did I fix this with the minimal necessary change?

Simple ≠ Small. Simple = Not Complected.

The simplicity policy is not a guideline. It is the prime directive. Return to it constantly.
</simplicity_reminder>
